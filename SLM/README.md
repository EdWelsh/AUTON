# SLM training workspace

The Small Language Model is the AUTON kernel's interface: you ask the machine, it
answers. This directory trains it, from datasets to a model file the kernel loads.

## The rule: training data is generated, never written

A corpus of plausible-sounding answers teaches a model to be confidently wrong. Every
answer here comes from a source of truth, and each row's `fact` field names it.

| Dataset | Rows | Generated by | Ground truth |
|---|---|---|---|
| `datasets/os_chat.jsonl` | 944 | `tools/build_corpus.py` | what the kernel itself prints: its roles, device knowledge base and system queries |
| `datasets/hardware_kernel.jsonl` | 628 | `tools/build_hardware_corpus.py --profile kernel` | this machine's CPU: QEMU's default `qemu64` model (`agent/hardware/isa/qemu.json`) |
| `datasets/hardware_reference.jsonl` | 30,848 | `tools/build_hardware_corpus.py` | `agent/hardware/`: the vendor registry, instruction-set tables, CPUID bits and silicon exceptions. **Host-side only**: it does not fit the kernel tokenizer |
| `datasets/os_tasks.jsonl` | 12 | by hand (legacy; the e2e spine's pipeline proof) | — |
| domain text, `.cache/slm/domain/` | 2.8M words | `tools/fetch_domain_text.py` (sources and licences in `data/sources.yaml`) | Linux docs, man-pages, QEMU docs; statistics only in `datasets/domain_text.stats.json` |

**Read [`DATA.md`](DATA.md) first.** The kernel's tokenizer is word-level with a 1,024-word
vocabulary, so the question for any data is whether it fits: `tools/vocab_budget.py`
measures that. The kernel training set is `os_chat` + `hardware_kernel` (929 words, 0%
`<unk>`).

`os_chat.jsonl` and `hardware_kernel.jsonl` are about *this machine*.
`hardware_reference.jsonl` is reference knowledge: who holds PCI vendor id `1d17`, whether
`znver1` has FMA4. It has 13,718 distinct words, so at the kernel's vocabulary 15% of its
answer tokens, exactly the ids and names that carry its facts, would be `<unk>`; it is for a
host-side model.

Regenerate after the tables change. The SLM tests fail if any of the three generated
datasets differs from what its generator produces now (`tests/test_chat_corpus.py`,
`tests/test_kernel_data.py`, `tests/test_hardware_corpus.py`); `os_tasks.jsonl` is
hand-written and domain text is a cache, so neither is checked:

```bash
python SLM/tools/build_corpus.py --output SLM/datasets/os_chat.jsonl
python SLM/tools/build_hardware_corpus.py --profile kernel          # hardware_kernel.jsonl
python SLM/tools/build_hardware_corpus.py                           # hardware_reference.jsonl
python SLM/tools/fetch_domain_text.py                               # domain text (cache only)
```

To grow `hardware_reference.jsonl`, grow the tables: the vendor spec agents
(`scripts/vendor_research.py`) propose vendor documents and derive cited records, and
each merged record becomes more rows on the next generation.

## Pipeline

The SLM swarm runs this for you in a testing area: `scripts/slm_run.py start <name> --goal ...`
(output in `.artifacts/slm/<name>/`). By hand:

```bash
pip install -r SLM/requirements.txt                       # torch and friends; heavy

python SLM/tools/vocab_budget.py --together SLM/datasets/os_chat.jsonl SLM/datasets/hardware_kernel.jsonl
python SLM/tools/tokenizer.py --input SLM/datasets/os_chat.jsonl --vocab-size 1024 \
    --output vocab.json --tokenize-to tokens.jsonl        # vocab + token stream
python SLM/scripts/train.py --config SLM/configs/chat_tiny.yaml --dataset tokens.jsonl
python SLM/scripts/evaluate.py --help                     # score a checkpoint
python SLM/scripts/quantize.py --help                     # INT8 / INT4
python SLM/scripts/export_auton.py --help                 # the kernel's model file (AUTON format)
tests/kernel/neural_parity.sh model.bin final.pt vocab.json   # kernel forward pass == PyTorch
scripts/eval.sh --model model.bin                         # the chat eval: >=70% / <10% garbage
python SLM/scripts/export_gguf.py --help                  # GGUF / ONNX: host tools only
```

`configs/` holds model sizes from `tiny_10M` to `large_500M`; `chat_tiny` and
`chat_small` are the sizes the kernel's chat actually ships.

The kernel also carries lookup tables in the model file, so the model does not have to
memorise them: `tools/build_device_table.py` packs the PCI and USB registries and
`tools/build_errata_table.py` the errata. A lookup cannot hallucinate; prefer one.

## Layout

| Path | What |
|---|---|
| `datasets/` | the corpora above |
| `tools/` | corpus generators, tokenizer, device and errata tables, model-file format (`auton_format.py`), scoping eval |
| `scripts/` | train, evaluate, quantize, export |
| `model/` | the decoder-only transformer, config and checkpoints |
| `configs/` | model sizes |
| `manifests/` | per-image scoping (`doom.json`, `webserver.json`): what a scoped image's model may talk about |
| `tests/` | `PYTHONPATH=SLM pytest SLM/tests/`; torch-dependent tests skip without torch, and say so |

The specification the SLM is built to is in [`agent/slm_spec/`](../agent/slm_spec/)
and [`agent/kernel_spec/subsystems/slm.md`](../agent/kernel_spec/subsystems/slm.md).
