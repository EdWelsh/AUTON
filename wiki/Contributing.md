# Contributing

The full guide is [`CONTRIBUTING.md`](https://github.com/EdWelsh/AUTON/blob/HEAD/CONTRIBUTING.md).
The rules that matter most:

1. **A test must be able to fail.** Run it against a deliberately broken input before you
   trust it. A gate suite gets a `--self-test` against its reference and, where possible, an
   `--inject` score.
2. **Exit codes carry meaning:** 0 pass, 1 generated wrong, 2 not generated.
3. **Don't let a gate demand what it doesn't gate.** If a suite needs something outside its
   subsystem, supply a spec-derived stand-in and say so on stderr.
4. **Agents write kernels; the repository holds the agents.** Never commit a generated tree.
5. **Hardware facts need a source.** Derived tables are regenerated by their tools, never
   edited; hand-written exception rows carry a source and stay `verified: false` until
   checked; vendor documents are never committed.
6. **Training data is generated.** Change a generator or its source, never a dataset row.
7. **A changed harness is a changed experiment.** Pre-register a run before it starts.

## Edit this wiki

The pages are in [`wiki/`](https://github.com/EdWelsh/AUTON/tree/HEAD/wiki). Change them in a
pull request, then:

```bash
python scripts/wiki.py build      # regenerate Specialists and the numbers on Home
python scripts/wiki.py check      # every [[link]] resolves; generated pages current
python scripts/wiki.py publish    # push to the GitHub wiki (needs write access)
```

Reporting a vulnerability: [`SECURITY.md`](https://github.com/EdWelsh/AUTON/blob/HEAD/SECURITY.md).
