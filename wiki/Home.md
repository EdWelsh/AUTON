# AUTON

**An agent swarm that writes an operating system kernel with a small language model inside
it, and the gates that decide whether it worked.**

AUTON's kernel has no shell. It boots to an `auton>` prompt and you configure the machine by
asking it. We don't write that kernel: agents do. This repository holds the agents, the
specifications they are held to, the gates that judge their output, the hardware knowledge
they draw on, and the data the on-device model learns from.

## Status, honestly

There is no finished kernel, and this wiki will not imply otherwise. What exists is
everything that judges a kernel, and a swarm that has produced two results that pass their
frozen gates: a TFTP server (w14) and a VirtIO console driver (R8, campaign 2). The first full
generation campaign passed 1 of 12 runs; every failure was investigated and most were harness
defects, now fixed. See [Status and Roadmap](Status-and-Roadmap).

## The two rules everything else follows

1. **A test must be able to fail.** Gates are frozen before a run, scored by injected bugs,
   and report "not generated" (exit 2) separately from "generated wrong" (exit 1).
2. **A fact needs a source.** Hardware facts cite a document and page; training answers are
   generated from ground truth; a document never proves an instruction is present.
